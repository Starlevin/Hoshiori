# 前端预览检查、修复与对比

日期：2026-11-04。对照正式版 v0.7.8 / f66e43d；原预览分支 feature/frontend-miuix-preview / 53e7412。

## 判断

预览版的明确功能收益是 OLED 纯黑和 RGB 取色器。图标线条从1.8变为2.0并改成部分圆角，是风格选择，不能据此认定整体更好。底栏、Backdrop、Capsule及其手势源码没有变化，液态玻璃没有新增实现；没有同条件帧率基准，不宣称性能优于正式版。

建议保留纯黑与取色器，在完成真机检查和视觉确认后再考虑合入正式版。此次保持独立预览发布，不替换正式 v0.7.8。

## 已定位与修复

1. 原 v0.7.9-preview 的 GitHub Release 没有任何附件；说明写 unsigned，源码构建版本却仍为0.7.8。改为明确版本0.7.9-preview.1、versionCode19、可校验的正式证书签名 Release 构建。应用名“星栞 · 前端预览”，包名com.glasssign.app.preview，与正式版并排安装；预览明确标记 prerelease，不提升正式更新通道。
2. 原 RGB 色块、HEX 与应用按钮共占一行，通道标签和数值固定窄宽，大字号可能挤压。拆成色块/HEX行、三条有独立标签和数值的通道、单独应用按钮；添加通道无障碍名称，拖动只更新局部草稿，点击应用才写主题设置。
3. RGB草稿使用rememberSaveable。设备旋转检查进一步发现父外观面板不恢复，使子草稿无法恢复；仅保存非敏感外观面板显示状态，危险操作弹窗继续按原规则关闭。
4. OLED文案补充自选背景规则：无背景页面及卡片可使用纯黑；自选图片继续按背景设置显示，不擅自删除或隐藏用户图片。
5. Windows隔离数据库测试遇到两个SQLite WAL创建失败；保留完整UUID，移除冗长测试文件名前缀后，全部14项隔离数据库集成测试及整套回归通过。没有更改生产数据库名称或清理真实数据。


## 视觉证据

在同一MuMu Android15/API35、720×1280、相同深色/纯黑开关及默认种子色条件下，原生截图取样：

| 位置 | 正式v0.7.8 | 预览 |
| --- | --- | --- |
| 卡片空白处(600,250) | RGB(15,15,15) | RGB(0,0,0) |
| 页面空白处(300,1100) | RGB(3,3,3) | RGB(0,0,0) |

这证明这些取样位置变为纯黑，不证明整屏功耗或帧率改善。自定义背景、按钮及文字本来就不应全部变黑。对比截图为真实应用输出，HTML对照页只并排展示，不修改截图像素。

## 验证边界与交付

最终Release构建通过；400项JVM测试，失败0、错误0、跳过0；Lint0错误、60警告、2提示。修复后的设备验证包括独立安装、纯黑取样、RGB草稿旋转保持、显式应用保存，以及200%字号下通道名称/数值/按钮可完整查看。草稿实测从#4263C7改为#C463C7，旋转后仍为#C463C7。结果记录于BUILD_INFO.json及测试报告。预览版与正式版使用独立数据和Keystore作用域；不能宣称跨包账号自动迁移。没有进行真实第三方签到请求。

最初400项中两个Windows测试夹具失败的记录保留在私有工作日志中，最终通过结果必须以最终测试XML为准，不用旧成功报告覆盖失败。新加两项主题测试覆盖纯黑容器、极端种子色的文字对比度，以及浅色模式不受纯黑开关影响。

发布附件包含签名APK、固定源码、构建与签名信息、测试/视觉证据、对照HTML及SHA256。正式包和旧预览标签保留；旧空预览说明指向修复后的编号预览，不重打历史标签。

遗留：尚未在物理OLED真机检查面板观感、色彩和功耗；尚无低端真机长期帧率对比；第三方平台和旧Android实号能力不属于本次视觉验收。用户对图标风格的最终偏好仍以实际观感为准。
