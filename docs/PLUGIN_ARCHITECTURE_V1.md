# 星栞签到插件架构 v1（开发分支提案）

状态：设计与接口基础开发中，**非已发布功能**。主工程仍为 Hoshiori 0.6.0；不能直接安装 LingQian APK 作为星栞插件。

## 产品定位

- 星栞为唯一主程序；二次元游戏签到作为主体验和首页重点。
- 非游戏签到（例如 WorkBuddy CN、Qoder CN）进入「扩展插件」分组，不塞入游戏角色目录。
- 插件可各自提供：账号授权流程、账号 / 角色 / 任务发现、每日状态查询、领取、余量查询、错误诊断。
- 星栞统一：账号与授权加密保存、任务队列、去重、通知、失败重试策略、日志、更新、权限审查。
- 扩展插件账号与游戏角色不自动合并；手机本机 HTTPS 访问，不依赖服务器。

## V1 插件等级

1. **内置插件（第一阶段，当前开发）**：官方项目审核的 Kotlin 插件，随 APK 一起编译。名称和接口可统一，但不能在运行中随意安装未知二进制。优先移植领签的 WorkBuddy CN、Qoder CN。
2. **声明式插件包（第二阶段）**：从受信任来源安装有签名和版本的 JSON 配置包，宿主只执行白名单内的模板请求与状态判断。配置仅描述固定 HTTPS 主机、方法、请求模式和解析规则，**禁止任意脚本及动态代码加载**。维护者审核上游接口、许可证和授权方式。插件更新不应替换主程序数据库。
3. **高权限原生扩展（未来评估）**：独立 APK + Android Binder/AIDL 服务，签名校验与逐项能力授权，单独 UID 沙箱。没有完整威胁模型与真机安全验收前不支持安装第三方 DEX/JAR 或不受限 JS。

## 兼容约束

必须保持 Hoshiori 0.6.0 的 `applicationId=com.glasssign.app`、debug suffix、现有数据库和 Keystore 别名、WorkManager 唯一任务名称与更新签名语义。**禁止**复制 LingQian 的独立 `MainActivity`、`CheckinJob`、`Vault` 到主程序；只迁移单个插件的网络协议和授权步骤，并通过宿主注入的存储与调度能力运行。既有「首页 / 绑定 / 记录」三个游戏入口保持原语义；「插件中心」以二级页面入口开始，不直接更改底部三个主要标签。

## 建议宿主契约

- `PluginDescriptor`：稳定 ID、显示名、类别、版本、HTTPS 主机白名单、授权类型、权限声明、支持的任务类型。
- `CheckinExtension`：discoverTasks / checkStatus / checkin / queryQuota；所有动作经宿主统一调度。
- `PluginRegistry`：只加载审核过的内置/签名插件，注册时校验重复 ID、主机列表、版本。
- `HostHttp`：HTTPS 443、固定域名白名单、无重定向、请求和响应大小限制；不允许从远端响应中获得新的任意目标地址。
- `HostCredentialVault`：Android Keystore 按账号隔离，限制 token 暴露，禁止插件跨账号读取和记录敏感内容。
- `HostTaskStore`：按 `Asia/Shanghai` 自然日 + 插件 ID + 账号 ID + task ID 去重；提交网络异常标记 `uncertain`，避免盲目重发。
- 任务结果区分 `success`、`already`、`needs_action`、`waiting_network`、`uncertain`、`failed`、`no_activity`。没有活动不等于已签到。

## 登录与风控

- WorkBuddy 国内版：复用官网浏览器授权 state/poll；refreshToken 轮换后原子更新，加密持久化，避免和原客户端同步混用时互相作废。
- Qoder CN：复用设备码 PKCE S256 登录，凭据只存在星栞本机；活动接口每日状态查询优先，服务端明确可领才 POST。
- Qoder 国际版设备风控与 WorkBuddy 国际版每日对话活跃机制**不是国内版签到的简单开关**；不在首批接入。
- 上游私有/非官方接口可能变更，收到验证码、429、异常结构、未确认结果时必须停止或提示用户；不得绕过验证或伪报到账。

## 任务与界面

**首页**：优先展示原神、星穹铁道、明日方舟、终末地等游戏签到；折叠卡显示扩展插件执行摘要。**绑定**：保留现有游戏角色多选，新增「其他平台插件」入口；插件自行描述授权方式，不冒充游戏角色。**记录**：同一个历史流里显示来源（游戏／插件）、账号、状态、积分/奖励（只有官方响应明确才显示）、错误来源。**插件中心**：浏览内置、已启用、待更新、兼容版本，不自动添加未获授权的账号。

## 分步交付与验收

- Phase 0：保持现有 main 分支；新建 feature 分支，定义安全的插件描述、注册契约与单元测试，给出迁移边界。
- Phase 1：移植两个内置插件的授权、查询、领取到宿主 API，接入 encrypted vault、WorkManager、结果记录，补模拟接口测试。
- Phase 2：添加插件中心 UI、用户授权确认、多账号管理、任务级状态显示及来源过滤；完成 Android 模拟器与真机验证。
- Phase 3：构建带签名的声明式插件分发、可信目录与更新验签、回滚与协议版本协商。未验收前不发布第三方插件安装能力。

## 仓库关系

- [Starlevin/Hoshiori](https://github.com/Starlevin/Hoshiori)：主程序、SDK 契约、UI、任务和账户存储。
- [Starlevin/LingQian-Android](https://github.com/Starlevin/LingQian-Android)：原有独立 App 的协议参考与验证基线。其测试 APK **不是** Hoshiori 的可热插拔模块。
- 迁移时优先提取纯协议层、保留原提交来源和许可说明。独立 App 只作为参考，不将两个 `applicationId` 组合成一个安装包。

## 当前未完成

当前 feature 分支只作为插件协议与技术方案的开发阶段；不能宣称 WorkBuddy/Qoder 已经出现在星栞的正式版，也不能宣称两个平台的真实签到通过。主程序稳定版 v0.6.0 与其用户数据不应受影响。
