# v0.7.3 森空岛登录修复与交接

日期：2026-11-02。版本0.7.3，versionCode13，原应用标识、签名和schema5保持兼容。此版本修复登录采集，不自动发起签到，也不修改已有绑定或历史。

## 问题与修复

用户在MuMu绑定森空岛第二个账号时，截图显示“身份未提供”“授权失效，请重新导入”和未读取到游戏角色。身份缺失与官方接口401应分别判断；不能将缺少平台ID直接等同于账号没有明日方舟角色。

只读审查[森空岛官方登录页](https://www.skland.com/login)加载的[公开前端脚本](https://web.hycdn.cn/skland/site/index.e97a92.js)发现：`SK_SHUMEI_DEVICE_ID_KEY`保存JSON对象，其中`id`为设备标识，`timestamp`为缓存时间。旧采集代码只解开JSON引号，把整个对象文本写入`dId`，与官方页面使用的设备标识不一致。

现从对象提取字符串`id`，登录环境连续采样和最终适配器凭据共享同一解析逻辑。兼容旧版原始字符串和带JSON引号的字符串；对象损坏、字段缺失、非字符串、空白或空值不能成为完整会话。缓存时间变化不视为账号或设备变化。没有生成随机指纹或放宽授权判断。

新增三个JVM回归用例覆盖官方对象格式、异常对象和缓存时间变化。现有连续采样、账号切换隔离及缺字段用例继续保留。

## 继续处理

如重新授权后仍出现401，保留旧账号与历史，采集脱敏的请求方法、官方主机、状态码及操作阶段；继续核对官方公开协议与会话上下文。不要输出Cookie、令牌、密码或设备标识，不盲目重试签到提交。

只在用户已退出输入后覆盖升级，不先卸载，不执行清数据库的完整测试夹具。设备测试使用非破坏性导航、绑定布局和实际渲染用例。
