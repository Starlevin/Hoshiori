# 星栞 Hoshiori v0.7.7 交接与验证报告

日期：2026-11-03。正式版 versionCode 17，包名 `com.glasssign.app`。基线为 v0.7.6（72aaade），在原项目增量修改。四页导航、绑定顺序、原生 Compose、本机执行及历史数据保留不变。本轮由 DSH 分担协议、执行持久化、界面三个任务，Codex 集成审查并修正跨模块契约与补充隔离数据库测试。

## 根因与证据边界

已定位：旧通用 code=0 解析返回 success，实际仅说明受理，落库又依赖消息文字猜测来源；塔吉多提交缺少二次状态核对；再次点击时先做目标发现/令牌续期，再检查当天已完成目标，因此不必要的授权 POST 仍可发生。HTTP 非 2xx 响应体的业务码原先被丢弃。本机缓存结论曾沿用官方来源，容易被误解为本轮再次查询。列表底部固定留白、状态省略和筛选区域布局也存在明确缺陷。详见 [审查报告](v077-audit.md)。

未定位：用户 10:40:54 的塔吉多 HTTP 402 服务端真实含义。旧响应体没有保存，不能还原业务码，也没有通过重复真实请求试探。不能宣称已修复平台风控、参数或授权服务，也不能解释为要求付费。本轮修复的是请求顺序、证据保留和安全分类；真实接口恢复仍待验证。

## 修改交接

| 文件/模块 | 最终行为 |
| --- | --- |
| local/Protocol.kt、Providers.kt | SignResult 显式包含来源、HTTP/业务码、核验方法/时间、可重试性和 executionId。SUCCESS、ALREADY_SIGNED、ACCEPTED、VERIFYING、FAILED、AUTH_REQUIRED、UNKNOWN 统一展示语义；兼容旧存储枚举。HTTP 成功不等于业务成功。非 2xx 仅提取有界、脱敏业务码，不存原始响应或授权。HTTP 402 为明确错误但不擅自失效授权。 |
| 米游社、森空岛、塔吉多适配器 | 已验证的只读状态接口用于二次核对。塔吉多只有 gameId 的状态不能直接归属所有角色；多角色且归属不明时保留 UNKNOWN 并停止提交。社区没有已验证核验接口则保持 ACCEPTED，不编造接口。 |
| local/RunPlanning.kt、LocalSignEngine.kt | 在目标发现与令牌续期前评估可信绑定及当天目标保护。仍需发现的新目标正常执行；社区首签不会因只遍历游戏绑定而漏掉。过程串行并携带 executionId。 |
| local/SignRepository.kt、MigrationSnapshot.kt、data/Models.kt | schema 6 增加结果元数据，迁移保留账号、授权、角色、历史及 sign_guards。私有迁移快照包含全部七张业务表。事务 claim 同查历史与保护表，防并发、当天重复与清历史后重复提交；未知结果和非重试错误不自动重发。 |
| 授权及缓存策略 | 未知 402 只更新诊断说明，不篡改既有授权状态或上次确认时间。明确登录失效才要求重新授权。显式重新授权只解除已识别授权拒绝，不解除受理或未知 402 的重复保护。成功缓存标为 local_cache，保留原证据时间，绝不冒充新一次官方查询。 |
| data/RecordPresentation.kt、ui/SignFeedback.kt、SignScheduler.kt | 首页、记录与通知使用相同状态语义。待确认不计入确认成功；只读核验不确定则保留旧受理证据。失败修复/重试入口遵循 retryable，避免无限 POST。 |
| ui/HoshioriScreen.kt | 长状态可换行，详情完整展示错误与证据字段；筛选器横滚、提示及选中项自动进入可视范围。成功绿、已签蓝绿、待确认琥珀、失败红、未知灰，均保留文字。 |
| ui/LiquidDock.kt | 以整个悬浮层实测高度计算列表底部 contentPadding，包含导航 Insets 和悬浮距离；保留动态背景采样、折射、拖动胶囊及缓存。减弱双重边缘高光，描边缩至 0.6dp。未替换成实心底栏。 |

迁移只会把历史“成功但来源为受理”的记录降为受理，绝不批量提升成功。业务日期、UUID 账号及目标签到键隔离；平台固定关联账号，不以昵称合并账号。密码、验证码、Cookie、令牌和真实数据库不进入源码或发布附件。
